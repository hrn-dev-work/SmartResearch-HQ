# Project plan: SmartResearch-HQ

> Entry point for goals and strategy. Canonical specs: [requirements.md](./requirements.md) / [design.md](./design.md) / [architecture.md](./architecture.md).

## 1. Purpose and strategy

Automate cross-border EC (Shopee, etc.) product research and matching that is today manual, via **scraping + candidate matching + human-in-the-loop**.

**Dual mode (portfolio + production)** on one codebase.

| Edition | Purpose | Visibility | Spec |
|---------|---------|------------|------|
| **Portfolio** | Hiring / client demo | Frontend + docs + Mock API | No external APIs; E2E on fixtures |
| **Production** | Real operations | Private repository | Full Playwright / matching / Sheets |

Portfolio may omit scraping evasion logic and proprietary prompts.

## 2. Tech stack

| Layer | Technology | Role |
|-------|------------|------|
| Frontend | Next.js 16, TypeScript, Tailwind CSS | Dashboard and review UI |
| API | FastAPI (Python 3.11+) | REST, jobs, status |
| Scraping | Playwright (Python) | Shopee SOLD extraction (production) |
| Matching | Pluggable (`MATCHING_PROVIDER`) | Shopee → Amazon ASIN candidates (max N) |
| Queue / DB | Redis + ARQ, PostgreSQL | Async processing, history |

### Matching policy (2026-05)

Avoid dependency on Gemini quota; **non–AI-first** architecture.

| Provider | Description | Priority |
|----------|-------------|----------|
| `amazon_search` (**default**) | Shopee title → Amazon keyword search | Phase 2 main |
| `none` | No auto candidates; manual ASIN | Zero quota |
| `gemini` | Multimodal structured JSON | Optional, later |

## 3. Workflow (before / after)

**Before (manual, ~5–10 min per item)**

1. Find SOLD items on Shopee manually  
2. Match on Amazon via Lens, etc.  
3. Paste ASIN / URL into spreadsheet  

**After (this system, seconds per review)**

1. Submit Shopee shop URL on dashboard  
2. Backend: SOLD extract → candidate matching (async)  
3. Review UI shows Shopee source + Amazon candidates  
4. Human picks (or enters ASIN) → export to Sheets  

Core value: **human-in-the-loop**. No automatic final ASIN selection.

### Milestones

```
M1: Mock research from frontend (portfolio)     ← reached

M3: Review → Sheets E2E
M4: Public GitHub + demo URL
```

## 5. Design highlights

- **Matching ops**: Fixed candidate schema (asin, url, title, confidence). Structured JSON only when using Gemini.
- **Errors**: CAPTCHA / IP block per worker; DLQ after retry limit.
- **State**: `AI_INFERENCE` = matching in progress (legacy name). Progress exposed to frontend.
- **Local dev**: portfolio needs no Postgres / Redis. `bash scripts/bootstrap-local.sh` generates `.env`.

# プロジェクト計画書：SmartResearch-HQ

> 概要・戦略の入口。詳細仕様は [requirements.md](./requirements.md) / [design.md](./design.md) / [architecture.md](./architecture.md) を正とする。

## 1. 目的と基本戦略

手作業で行われている越境EC（Shopee 等）の商品リサーチ・名寄せを、**スクレイピング + 候補マッチング + Human-in-the-loop** で自動化する。

**二刀流（表裏一体）** で同一コードベースを運用する。

| 版 | 目的 | 公開範囲 | 仕様 |
|----|------|----------|------|
| **表（portfolio）** | 転職・提案デモ | フロント + docs + Mock API | 外部 API なし。フィクスチャで E2E 完走 |
| **裏（production）** | 実運用・副収入 | Private リポジトリ | Playwright / マッチング / Sheets フル実装 |

表版ではスクレイピング回避ロジック・プロンプト等のコア実装は非公開可。

## 2. 技術スタック

| 層 | 技術 | 役割 |
|----|------|------|
| フロント | Next.js 16, TypeScript, Tailwind CSS | ダッシュボード・レビュー UI |
| API | FastAPI (Python 3.11+) | REST、ジョブ投入、ステータス配信 |
| スクレイピング | Playwright (Python) | Shopee SOLD 商品の抽出（裏版） |
| 候補マッチング | プラガブル（`MATCHING_PROVIDER`） | Shopee → Amazon ASIN 候補（最大 N 件） |
| キュー・DB | Redis + ARQ, PostgreSQL | 非同期処理、履歴保存 |

### 候補マッチング方針（2026-05 改定）

Gemini API のクォータ制約を踏まえ、**AI（マルチモーダル）に依存しない**構成を採用。

| プロバイダ | 内容 | 優先度 |
|-----------|------|--------|
| `amazon_search`（**既定**） | Shopee タイトル → Amazon キーワード検索 | Phase 2 本線 |
| `none` | 候補自動生成なし。レビュアーが ASIN を手入力 | クォータゼロ |
| `gemini` | 画像+テキスト推論（Structured JSON） | 任意・後置き |

## 3. 業務フロー（Before / After）

**Before（手作業：1 件 5〜10 分）**

1. Shopee で SOLD 商品を人力で探す
2. 画像を Google レンズ等で Amazon 同一商品を探す
3. ASIN / URL をスプレッドシートに貼る

**After（本システム：レビュー 1 件数秒）**

1. ダッシュボードで Shopee ショップ URL を投入
2. 裏側で SOLD 抽出 → 候補マッチング（非同期）
3. レビュー画面に Shopee 元情報と Amazon 候補を表示
4. 人間が正解を選択（または ASIN 手入力）→ Sheets へ出力

価値の核は **Human-in-the-loop**。候補の自動確定は行わない。

```
M1: フロントから Mock リサーチ完了（portfolio）     ← 到達済み
M2: CLI で 1 セラー実スクレイプ + amazon_search
M3: レビュー → Sheets 出力 E2E
M4: 公開 GitHub + デモ URL
```

## 5. 設計上の重要ポイント

- **マッチング Ops**: 候補は固定スキーマ（asin, url, title, confidence）。Gemini 利用時のみ Structured JSON。
- **エラーハンドリング**: CAPTCHA / IP ブロックはワーカー単位で失敗。リトライ上限後 DLQ。
- **ステート管理**: `AI_INFERENCE` は「候補マッチング中」（名称は後方互換）。フロントへ進捗を返す。
- **ローカル開発**: portfolio は Postgres / Redis **不要**。`bash scripts/bootstrap-local.sh` で `.env` 自動生成。
